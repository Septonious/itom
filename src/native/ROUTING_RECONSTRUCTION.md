# 1.5.1 routing reconstruction (development only)

Base: 38b59f00b553b6fb8816547f0dbfc79c205ecc83. Transport scheduler and server code unchanged.

This adds an immutable Go classifier based on CSQTT RC8's documented native JSON and rule order, parsing V2Ray GeoSite/GeoIP protobuf and two domain lists. The existing Host.Route callback remains the fallback when no new native policy is supplied. Opt-in runtime config fields RoutingPolicy (JSON object) and RoutingDataDir (private asset directory) load the classifier before opening provider sockets. The classifier is used for DNS blocking and actual TCP destination routing; re-evaluates with resolved IP before opening the connection. Existing IPv6/UDP transport restrictions are not expanded.

The three mobile routing exports and ReplaceTun have provisional Go signatures; they are not a claim of binary compatibility. ReplaceTun consumes detached descriptors and leaves the old TUN intact on construction failure; existing flows on the old stack may be lost. Exact RC20 method descriptors are recovered from the SHA-256-verified release APK by the new workflow. RebindNetwork and SetNetworkType are not yet implemented: the old Host interface only protects sockets, and RecordNetworkEvent only records a bounded diagnostic event, not an actual rebind. Restoring network transitions requires the exact ABI, protected socket binding and provider recovery semantics. Do not substitute no-op methods.

Still needed: compare actual RC20 DEX descriptors with newly generated gomobile bindings; verify the real packaged GeoData against the loader; recover/adapt Android Gradle and UI from historical snapshot, including app-level exclusions and settings; run device/TUN handover, DNS and routing regression tests; resolve the prior a02 post-load P95 qualification failure; rerun 8-account screen and full matrix; build and sign matching APK and server. No release or existing APK modification is authorized by this experimental branch.

## RC20 ABI audit follow-up

The checksum-verified RC20 DEX declares org.itom.nativecore.mobile.Mobile.checkRouting(String,String,String,String):String; validateRoutingData(String):void; validateRoutingPolicy(String,String):void; and Client.replaceTun(long):void, rebindNetwork():void, setNetworkType(String):void. See Actions run 45829979571. Native CheckRouting now accepts four strings, including the optional IP address. The exact argument meaning/order and Java result semantics still require call-site verification; the first two arguments accept either JSON/directory order. SetNetworkType updates bounded native diagnostic state only, without speculative transport tuning. RebindNetwork is still outstanding: old account failure is terminal, so blindly closing all carrier sockets cannot implement a recoverable rebind. The real RC20 dataset has category-ru but no ru category; automatic matching now requires either alias, while explicit references still require the requested category to exist. The real-data test is rerun after the fix.
