# ITOM 1.6.0 RC1 — partial transport rework, field diagnostic only

Source tree: `0b4696f49aa8ccfae67e10d4177b8f1fc324785e`. Upstream RC23 `2d358a62530cceb73b9204a6e1a51334b4797f54`. Main is unchanged. No stable tag or release. Match APK, ingress and encrypted exit binaries; strictly require the new relay credit protocol. Use dedicated, completely cleaned test mailboxes; never run mixed revisions against the same mailbox. Do not connect multiple devices under the same identity yet. Keep RC20/RC23 backups and stop all endpoints before rollback/cleanup.

Active changes: independent receive/credit/receipt workers, range reassembly, bounded early gap repair, fair stream dispatch, publication and authenticated first-attempt receipt-aware account scoring, directional demand guard, async relay credit and strict negotiation, simulator cancellation fix. Ordinary CONTROL reservations are limited to 384, recovery reserve 128 (total 512); DATA remains 128 per segment to fit the existing byte budget. Fresh fast-provider feedback uses a 6 ms coalescing delay; slow or unknown paths retain their original delay. The independent urgent-receipt experiment was not selected.

The compact `v160` folder, codec, registry and reliable channel foundations are not the active carrier. Shared CONTROL folders and the old authenticated packet header remain. The unified controller, durable session-specific folder rotation/cleanup, and multi-device admission remain incomplete. This build is explicitly diagnostic, not the completed 1.6.0 transport.

CI correctness must pass before building; independent performance failures remain visible, not a promotion. Use real-network results to guide the remaining refactor.
