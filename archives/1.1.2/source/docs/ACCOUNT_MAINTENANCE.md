# Удаление аккаунтов и полная очистка — session-1

В главном меню `sudo itom` выберите **3. Почтовые аккаунты**.
Перед изменениями остановите службу пунктом **8** главного меню и все
клиентские проверки/другие процессы, использующие выбранный аккаунт.
Состояние systemd проверяется перед выбором и повторно перед выполнением операции.
Ошибка получения состояния не считается остановленной службой. Ручной
`itom serve` вне systemd менеджер не контролирует: его также нужно остановить.

## 3 — удалить аккаунт из ITOM

Введите ID аккаунта. Дополнительная строка подтверждения не нужна.
Удаляется подключение из серверной конфигурации. Сам ящик у почтового провайдера,
папки и письма остаются. Удалить можно и последний аккаунт; до добавления нового
сервер обмена и экспорт профиля работать не смогут.

После изменения состава аккаунтов экспортируйте профили обоих пользователей
заново и замените старые на клиентах. Удаление на сервере не отзывает ранее
выданные почтовые пароли: старый клиентский профиль технически ещё содержит их.

При удалении сохраняется запись ID/hostname/логин без пароля и сохраняются
локальные журналы. Повторное добавление того же hostname/логина возвращает
его прежний ID. Для другого ящика выделяется свободный, никогда не занятый
сохранённой записью ID. Так устранена коллизия `len(accounts)+1` после удаления
из середины списка. Ограничение — 10 активных аккаунтов, до 1024 записей об
удалённых подключениях. Это не криптографическое стирание старых страниц bbolt.

Конфигурации schema 1 читаются автоматически; первая операция добавления или
удаления аккаунта атомарно сохраняет schema 2. Прежний manager-1 такую
конфигурацию отклонит, чтобы не потерять историю ID. После этого не откатывайте
бинарник на manager-1. Формат CLI-профиля остаётся прежним, без истории аккаунтов.

## 4 — удалить все папки и письма аккаунта

Выберите ID. Менеджер подключится с проверкой TLS, покажет фактический список
папок и выполнит очистку без дополнительной строки подтверждения.
Операция относится к одному выбранному аккаунту,
ко всем доступным папкам и письмам, включая не относящиеся к ITOM.

Вложенные папки удаляются раньше родительских, с учётом разделителя LIST.
INBOX не удаляется: его содержимое очищается. Если сервер отклоняет DELETE
другой папки, выполняется попытка очистить её содержимое. Очистка использует
UID STORE +FLAGS.SILENT (\Deleted) и CLOSE, затем проверяет отсутствие писем.
После подтверждённого отказа DELETE и успешной очистки выполняется ещё одна
попытка DELETE: некоторые серверы разрешают удалять только пустые папки.
Результат показывает удалённые, сохранённые пустые и неочищенные папки.
После DELETE также выполняется попытка убрать подписку на папку; отказ
UNSUBSCRIBE выводится отдельно и не отменяет уже подтверждённого DELETE.

В конце выполняется повторный LIST. Неожиданные/неудалённые папки, ошибки
доступа и разрыв соединения не выдаются за полную очистку. Операция не атомарна:
при сбое часть папок уже может быть удалена. Повторный вход показывает текущее
состояние. Письма, поступившие после проверки, и невидимые этому IMAP-логину
папки нельзя считать удалёнными. Сервер провайдера может заново создать
обязательные папки. Максимум 4096 папок, 1024 байта на имя, ограничение ответа
4 MiB, 30 секунд на команду и 10 минут на проход. При превышении операция
завершается ошибкой, а не усечённым сообщением об успехе.

Протокольная основа DELETE/INBOX и иерархий: RFC 9051, §6.3.5:
https://www.rfc-editor.org/rfc/rfc9051.html#section-6.3.5

## Журналы после очистки

Очистка не удаляет конфигурацию аккаунта, UID пользователей, ключи или журналы.
После запуска ITOM создаст свои папки снова. Удаление папки может сменить её
UIDVALIDITY; неизвестные APPEND и записи без доказательства результата **не
освобождают квоту автоматически**. Поэтому очистка не является способом
обнулить неопределённый долг: при исчерпанном control reserve потребуется
ещё не реализованное полное retirement/reconciliation. Не удаляйте журналы
для обхода этого ограничения. Эти изменения не подключают TCP/Android VPN.

## Проверка поставки

Текущий session-1: Linux Go 1.27.1, 16 packages, 242 passed test events,
0 failed/skipped, race/vet passed. Проверены удаление по выбору ID без typed
подтверждения, сохранение журнала, запрет при активной службе и частичный результат.
Реальные локальные TLS/STARTTLS IMAP-тесты проверяют вложенные и Unicode-папки,
защищённые папки, очистку INBOX и сетевой сбой. В этом прогоне обращения к
пользовательским аккаунтам не выполнялись. Бинарники и APK здесь не собирались.
