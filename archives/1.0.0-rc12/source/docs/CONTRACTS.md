# Контракты Android-оболочки

## Server profile и pairing

Vault JSON v2; encrypted envelope v1; profile schema v2; app settings v3; address routing v1; invitation v2; wire baseline v1. Профиль соответствует одному серверу с одним провайдером. User ID — строка `[1-9][0-9]{7}`, выданная сервером; полная идентичность `(server_id, user_id)`. Локальный profile ID и ссылки секретов при импорте переназначаются для изоляции; server ID, user ID и mailbox namespace сохраняются.

В этой оболочке для одного server ID хранится один профиль. Повторный импорт не перезаписывает существующий профиль/ключ. С native-ui-2 пользователь может вручную изменить локальные имя, server/user/pair ID, namespace, PSK и аккаунты через редактор. Это обновляет данные клиента; серверная регистрация и автоматический re-pairing ещё не реализованы. Локальный profile ID остаётся прежним, чтобы сохранить выбор и привязку сессии. User ID не меняется автоматически при переименовании или переподключении; явная ручная правка разрешена по новому требованию пользователя.

Поле provider ID задаётся один раз на весь профиль и применяется ко всем аккаунтам. Проверка не доказывает принадлежность произвольного hostname провайдеру: приглашение приходит по доверенному каналу; серверная выдача должна валидировать provider preset/allowed endpoints. Клиент отображает endpoints до подтверждения. Проверка синтаксиса/отпечатка сама по себе не аутентифицирует источник.

Размер приглашения ограничен 128 KiB UTF-8, глубина JSON — 32. Unknown fields, duplicate keys (включая Unicode escape), неверные схемы, истёкший expiry, отсутствующие/лишние credentials и CR/LF/NUL в LOGIN credentials отклоняются. PSK — ровно 32 байта canonical Base64. Параметры TLS требуют IMAPS и проверки сертификата; небезопасный переключатель отсутствует. Fixture содержит публичные тестовые значения и не используется как рабочий аккаунт.

QR поддерживает непосредственно текст JSON-приглашения в выбранном изображении. Один обычный QR не вместит большой bundle; для нескольких аккаунтов используйте JSON-файл. URL из QR автоматически не открываются и не загружаются. Камера и multipart QR остаются будущими расширениями.

## Хранилище

Один документ `VaultDocument` шифруется AES-GCM с новым 96-битным IV; AAD включает application ID и версию формата. Заголовок: `ITV` + байт 1; затем IV 12 байт, ciphertext и GCM tag. Ключ генерируется в Android Keystore; hardware backing зависит от устройства и не предполагается без проверки. Данные находятся в no-backup directory; `allowBackup=false`.

Mutex сериализует обновления; идентичная конфигурация не переписывается. `AtomicFile` записывает новый документ, выполняются явный fd sync и проверка ciphertext через openRead, затем публикуется public snapshot. После неоднозначной ошибки записи in-memory document сбрасывается и дальнейшие изменения заблокированы до перечитывания диска; успешное сохранение не объявляется. После finishWrite не вызывается failWrite, чтобы не повредить уже завершённую запись на старых Android. Ошибки расшифровки/инвалидации ключа не удаляют и не заменяют файл пустой конфигурацией. Секреты не входят в `PublicConfig` или diagnostics и не копируются приложением в clipboard автоматически. Строки паролей в Kotlin/JVM невозможно надёжно обнулить; массивы временных plaintext/decoded PSK очищаются по возможности. Разблокированный процесс приложения не считается изолированным от привилегированного доступа к памяти.

Редактор получает отдельный `ProfileEditSession` с текущей revision. Перед сохранением revision сверяется под тем же Mutex; устаревший черновик не перезаписывает новые данные. Обновление метаданных, credential maps и PairSecret — одна зашифрованная запись. Удалённые аккаунты удаляют свои секреты, ссылки остальных профилей не затрагиваются. У полного профиля все секреты обязательны. Неполные профили, сохранённые миграцией, читаются и редактируются, но не допускаются к подключению; Save требует все credentials и ключ, затем снимает incomplete flag. Secret refs уникальны между всеми профилями, лишние записи запрещены.

Черновик живёт только в ViewModel, переживает поворот экрана, но не записывается в SavedStateHandle, Bundle или plaintext-файл. После смерти процесса открываются сохранённые данные. Закрытие редактора сбрасывает черновик; экран защищён FLAG_SECURE, пароли и PSK скрыты с возможностью показа. Приложение не копирует их автоматически в clipboard; стандартные действия пользователя в полях не подменяются.

## Маршрутизация

Порядок групп неизменен: VPN → Block → Direct; без совпадения VPN. Внутри группы достаточно любого совпадения. При одновременно известных имени и IP проверяются оба в том же порядке групп. Домены нормализуются через Java IDN/STD3 + lowercase; финальная точка удаляется. `google.com` совпадает с собой и любым поддоменом по границе label. `.ru` — TLD. CIDR допускает ненулевые host bits и сравнивает только prefix. IPv4 с неоднозначными ведущими нулями, zones/brackets IPv6 и URL отвергаются. IPv4-mapped IPv6 остаётся семейством IPv6, а не неявным IPv4 alias.

Это чистая функция без DNS запросов. Полноценный DNS mapping, защита от обхода domain rules через альтернативный DNS и реальное применение IPv6/UDP ограничений — задачи data plane, а не функции UI. Наличие поддержки IPv6 CIDR в classifier не разрешает IPv6 transport.

Нативная область VPN задаётся раньше адресного classifier. `exclude_selected` даёт выбранным приложениям обычную сеть ОС и обход всех трёх групп. `include_selected` включает только выбранные приложения, для них сохраняются Block и явный Direct. ALL хранит пустой список. PackageManager использует текущий Android user/profile; shared UID выбирается целиком. Изменение активной политики создаёт новую generation. Реальная установка allowed/disallowed списков в VpnService.Builder ещё не подключена.

## Lifecycle и метрики

`SessionMachine` сериализует переходы; каждый Begin/Stop/Reject меняет generation. Reject атомарно публикует Error без промежуточного Connecting, истории и метрик. Connected/Metrics/Error от старой generation игнорируются. Error и Stop сбрасывают ставки/RTT/потоки и флаг интерфейса. В будущем реальный host обязан **фактически закрыть TUN до вызова fail**; сам reducer не владеет файловым дескриптором.

`SessionSnapshot` — источник UI и контракт будущего системного уведомления. В текущем коде foreground notification отсутствует. Rates хранятся в **битах в секунду**, `kbps=1000`, `Mbps=1_000_000`. RTT неизвестен как null, в UI «—». Пороговые цвета: ≤150 мс зелёный, 151–400 жёлтый, >400 красный. История ограничена 60 точками. `totalLines=2*accounts.size`; счётчик активных линий даст core. Ниже статистики нет segment stripe.

Оба варианта используют main UnavailableBackend: Start сразу публикует CORE_NOT_INTEGRATED. Сервисов сессии, таймеров синтетических метрик, boot receiver, автоподключения и фиктивного TUN нет. QS tile открывает UI. При старте удаляются только старые notification ID 71 и channel itom_demo. Разрешение POST_NOTIFICATIONS не запрашивается при попытке подключения до интеграции транспорта.

После успешной правки активного профиля сессия этого профиля запускается с новой revision. Проверяется актуальное состояние после записи: Stop во время сохранения не превращается в новое подключение. Изменение неактивного профиля не затрагивает текущую сессию. Эта ветка остаётся контрактом будущего backend; текущий backend не имеет активных сессий. totalLines учитывает весь набор аккаунтов, а не количество открытых сокетов.


## Миграция и идентичность приложения

Сохраняются прежние application IDs (`org.itom.client.dev` debug / `org.itom.client` release), имя файла, Keystore alias `itom.vault.v1` и AAD `<applicationId>:itom-vault:1`. Имя launcher/tile — ITOM. Совместимое обновление требует прежней подписи; переименование не переносит данные между разными пакетами.

Codec разбирает v1, проверяет прежние структуры/секреты и создаёт v2. Legacy demo IDs становятся кандидатами миграции; нетронутый встроенный профиль удаляется лишь при точном совпадении всех его полей и отсутствии любых связанных credentials/ключа. Любое изменение или сохранённый секрет сохраняет профиль. Полностью заполненные профили становятся обычными; остальные получают `incompleteProfileIds`. Сохранённый выбранный профиль сохраняется; при удалении выбранного демо берётся первый оставшийся, явно отсутствующий выбор остаётся null. Правила/настройки и реальные профили не изменяются.

Миграция увеличивает revision один раз и шифруется/проверяется до публикации. При ошибке загрузка блокируется, сброса vault нет. Повторное чтение v2 не мигрирует повторно. `largeText` и `demoProfileIds` существуют только во входной совместимости v1 и не сериализуются в v2; неизвестные/неправильные схемы отклоняются. Старые версии клиента не поддерживают обратное чтение v2.
