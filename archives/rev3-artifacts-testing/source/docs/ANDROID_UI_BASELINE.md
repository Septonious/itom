# ITOM · Android 0.4.0-dev4 · ui-final-1

Этап нативного UI и Android-оболочки завершён по исходникам. Пользователь принял оформление; в этой поставке убраны демо-функции, отображаемое имя изменено на **ITOM**, выполнен аудит кода и исправлены найденные дефекты. **Почтовый транспорт, настоящий VPN/TUN и сервер ещё не реализованы.** Кнопка подключения сообщает `CORE_NOT_INTEGRATED`, без вымышленных скоростей, подключения или фоновой сессии.

## Что изменено

- Удалены runtime mock, генератор метрик, искусственная задержка подключения, имитация ошибки, добавление демо-профиля и демонстрационный foreground service. Debug и release используют один backend, явно отклоняющий подключение до интеграции ядра.
- Установленное приложение и Quick Settings tile называются ITOM. Debug application ID остаётся `org.itom.client.dev`, чтобы обновление с той же подписью сохранило хранилище и ключи. Release ID остаётся `org.itom.client`; versionCode — 4005.
- Старый vault v1 мигрирует в v2 до публикации состояния. Удаляется только точное нетронутое встроенное демо без ключа и credentials. Изменённые профили и введённые секреты сохраняются. При нехватке секретов профиль отмечен «Требует настройки» и открывает редактор вместо подключения. Полностью заполненный профиль становится обычным.
- Проверка сохранения усилена: явный sync, чтение и сравнение записанного ciphertext; при неопределённом результате дальнейшие записи блокируются до повторного чтения. Идентичный выбор профиля или настроек не переписывает vault и не увеличивает revision.
- Повторная сборка после прохождения offline checks и получения lock удаляет прежний выходной APK/sha этой ревизии до запуска инструментов. Ошибка Gradle/SDK не оставляет старый APK как новый результат; другие файлы не затрагиваются.

Оформление, градиенты/bloom, светлый текст, цветная иконка, главная без скролла, произвольный угол орбиты, полный редактор и полноэкранный выбор приложений сохранены. Новый HTML не создавался. Подробный аудит: `docs/UI_FINAL_AUDIT.md`. Прежние `FIX*.md` и `NATIVE_UI*.md` описывают историю, а не текущее наличие демо.

## Локальная распаковка и сборка

Из PowerShell в папке со скачанным архивом:

```powershell
python .\ITOM_PHASE2_SOURCE_0.4.0-dev4_ui_final1.zip android --expect-revision ui-final-1 --accept-android-licenses
```

Нужны Python 3.10+, Windows/Linux x64 либо macOS x64/arm64 и доступ к официальным репозиториям инструментов и зависимостей. Флаг лицензий означает принятие [условий Android SDK](https://developer.android.com/studio/terms). Без флага принятие интерактивное. Если Python называется `python3`, замените первое слово.

ZIP проверяет SHA-256 исходников и распаковывается в новую папку `ITOM_ui-final-1_<суффикс>/itom/`, не перезаписывая прежние правки. Сборщик проверяет ревизию, выполняет offline checks, подготавливает недостающие JDK 17, Gradle 8.13, SDK 36 и Build Tools 35.0.0, затем запускает:

`:domain:test :app:lintDebug :app:compileReleaseKotlin :app:assembleDebug`

APK экспортируется только после успешного Gradle и проверки JUnit/Lint-отчётов. `QUERY_ALL_PACKAGES` имеет прежнее точечное обоснованное исключение Lint для полного каталога приложений; остальные ошибки блокируют сборку. Никаких новых baseline или глобальных подавлений.

Результат: `ITOM_ui-final-1_<суффикс>/itom/dist/ITOM_0.4.0-dev4_ui-final-1-debug.apk`. Рядом SHA-256, `build.log`, `build-report.json`, `test-summary.json`, полные Lint-отчёты и сводка. Для повторной сборки отредактированных распакованных исходников запускайте `python tools/build.py android --accept-android-licenses` из `itom/`.

Инструменты используют пользовательский кэш `~/.cache/itom-build`, либо `ITOM_BUILD_CACHE`/`--cache`. Существующие `JAVA_HOME` и Android SDK учитываются. Глобальные переменные, shell profile и HOME не меняются; root/Administrator не нужен. APK предназначен для ручной установки на Android 10+. Скрипт не устанавливает его на телефон и не подписывает production release. Сборка требует места под SDK/Gradle и зависимости; точная побитовая воспроизводимость между разными JDK/SDK пока не заявлена.

Обновляйте установленный debug APK с прежней локальной подписью. Изменено имя в launcher, а не идентификатор пакета. Удаление приложения удалит и его локальное защищённое хранилище. Обратная установка старого кода поверх vault v2 не поддерживается.

## Что уже работает в оболочке

- Десять Compose-экранов: главная, профили, редактор, импорт, правила, приложения, статистика, настройки, уведомление, диагностика.
- Редактор имени, User ID, Server ID, provider ID, namespace, Pair ID, PSK и IMAP-аккаунтов. Логины/пароли, host/port, ID/названия и enabled доступны для изменения. Один провайдер на весь профиль, обязательные IMAPS и проверка сертификата. Секреты сохраняются вместе с метаданными с защитой от устаревшей revision.
- Импорт JSON либо JSON из QR-изображения; проверка размера, глубины, схемы, срока, полей и ссылок секретов. Источник подтверждается пользователем. URL автоматически не открываются. Экспорт метаданных без ключей и credentials.
- Android Keystore AES-GCM и AtomicFile в no-backup directory. Нет plaintext backup, автоматического экспорта секретов или внешней телеметрии. Черновики секретов находятся только в памяти; редактор/import защищены FLAG_SECURE.
- Чистая модель маршрутизации VPN → Block → Direct, domain/subdomains/TLD/IP/CIDR и проверка адреса по сохранённым правилам. До интеграции data plane правила не фильтруют системный трафик.
- Настоящий PackageManager-каталог, иконки, поиск и системные приложения; режимы all/exclude/include, проверка shared UID и удалённых пакетов. Единственный вход — «Правила → Приложения».
- SessionMachine с generation guards, bounded history и единицами kbps/Mbps. Сейчас измерения нулевые, RTT неизвестен; `totalLines=2*accounts.size` отражает конфигурацию, не доступность почты. Рабочее системное уведомление и его Stop вернутся вместе с реальным foreground VPN service. Экран уведомления содержит только состояние разрешения и переход в Android settings.
- Quick Settings tile открывает приложение для явного действия. Диагностика экспортирует только версии, состояния, счётчики и код ошибки.

IDE-only `@Preview` и тестовые fixtures оставлены для разработки и недоступны как пользовательские функции. Они не создают сессии, сервисы или почтовые соединения.

## Проверки и следующий этап

Здесь прошли **32 Python-теста**, проверки **4 Python / 12 XML**, границ source sets и финального source ZIP. Подготовлены **52 Kotlin/JUnit-теста**; их выполнение, Android compile/Lint и проверка на устройстве выполняются локально. APK, JDK/SDK и серверные бинарники здесь не собирались и не устанавливались. `reports/SOURCE_CHECKS.json` разделяет выполненные и ожидающие проверки; `docs/DEVICE_CHECKLIST.md` содержит сценарии обновления.

UI зафиксирован по запросу пользователя. Следующая работа — core/AAR, настоящий VpnService/TUN, DNS/routing, IMAP, серверная выдача UID/ключей/папок и измерения. G2 остаётся открытым. Команда обновления VPS из вручную загруженного `/tmp` бинарника появится вместе с серверной реализацией. Исторические 120 Мбит/с старого форка не являются измерением ITOM.
