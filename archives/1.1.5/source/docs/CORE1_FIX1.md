# core-1-fix-1 · 25 сентября 2026

Исправлен сбой установки Go из пользовательского лога: `WinError 183` на
каталоге `go-extract-*`. До Go-компиляции прежний запуск не дошёл.

## Причина и изменение

`tempfile.mkdtemp` сразу создавал временный каталог, а общий `build.extract`
требует отсутствующий destination и вызывает `mkdir(exist_ok=False)`.
`ensure_go` передавал уже созданный каталог напрямую. Это воспроизводится
для Windows ZIP и Linux/macOS TAR.GZ, а не связано с правами пользователя.

Теперь временная папка служит родителем. Внутри неё распаковщик создаёт новый
`unpacked`, проверяет наличие `go/bin/go.exe` либо `go/bin/go` и только после
успешной распаковки переносит дерево в постоянный каталог Go. Удаляется только
собственная временная папка. Защита распаковщика от перезаписи оставлена включённой.
Посторонние и неполные установленные каталоги не удаляются автоматически.

Кэш скачанного архива и закреплённый SHA-256 прежние. Если скачивание в прошлом
запуске завершилось успешно и файл сохранился, повторная загрузка не нужна.
Запускайте новый ZIP обычной командой из README; очистка кэша не требуется.

`core-build.log` создаётся перед bootstrap. Ошибки загрузки/распаковки содержат
traceback и стадию сбоя в логе; `core-report.json` содержит поле `stage`.
Ранее вывод мог ссылаться на ещё не созданный лог. Проверены остальные вызовы
общего распаковщика в JDK/Gradle/SDK: они уже используют дочерний каталог.

## Проверки

Добавлено шесть regression tests поверх прежних 44. Они используют настоящие
`ensure_go`, проверку SHA-256 кэша и `build.extract`, с небольшими локальными
ZIP/TAR.GZ fixtures. Go из fixtures не исполняется; сетевой вызов запрещён тестом.

Покрыты свежая установка в пути с пробелами, повторное использование установленного
Go и скачанного архива, ошибка посреди распаковки с успешным повтором, отсутствие
executable, сохранность неполного/чужого каталога, ошибка финального перемещения.
Существующий тест раннего bootstrap failure дополнен проверкой фактического
лог-файла и traceback.

До исправления fresh-install test падал с FileExistsError во всех трёх вариантах
layout. После исправления прошли **50 Python-тестов**, 7 Python AST, 12 XML и
source-set checks с EncodingWarning как ошибкой. Проверки выполнялись в Linux;
Windows/macOS layouts смоделированы, нативный запуск Windows не выполнялся.
Go tests/компиляция, APK/server build и реальная установка toolchain здесь не
выполнялись. Их результат нельзя выводить из прохождения offline checks.

Go-код, зависимости, wire fixture, Android и транспортный концепт не менялись.
Это исправление упаковщика/установщика, не новый транспортный milestone.
