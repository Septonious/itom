Это приближение по клиентским логам, без верифицированных server timing/rate limits. Два успешных прогона не доказывают статистическую надёжность настоящего провайдера.

## Изменения

GRANT_RECONCILE с собственной историей wallet; ранний ACK регистрации descriptor без возврата физической квоты; empty FETCH backoff; 500 ms grace после DATA commit; byte pressure cleanup; переход неотправленной работы всему пулу без траты физических попыток; два quiet reader и предпочтение для коротких DATA; сериализация их cleanup; максимум5 bulk APPEND; обход read inactivity через существующий cleaner без переподключений и без DATA retry, с переносом bounded UID discovery; governor RTT/скорости сохранён.

## Команды

Сборка в Windows PowerShell:

```powershell
python .\ITOM_TRANSPORT_FIELD35_SOURCE.zip all --expect-revision transport-s1-perf5-field14 --accept-android-licenses
```

Обновление VPS amd64, когда соответствующий бинарник уже в `/tmp`:

```bash
chmod 755 /tmp/itom-linux-amd64 && sudo /tmp/itom-linux-amd64 install
```

Обновить Android и VPS одной ревизией: старый peer без GRANT_RECONCILE отвергается. Для VPS arm64 нужен соответствующий arm64 бинарник. Installer сохраняет состояние и откатывает бинарник при неудачном рестарте активной службы.

Машиночитаемые результаты, SHA-256 кода и полный core-report находятся в `docs/FIELD35_TEST_RESULTS.json`; первичные журналы приложены отдельно.
