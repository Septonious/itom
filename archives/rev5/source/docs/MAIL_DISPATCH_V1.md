# Почтовый управляющий канал — dispatch-1

## Что уже выполняется

`mailbox.Dispatcher` владеет очередью одного соединения с одним IMAP-аккаунтом.
Маршруты пользователя содержат только его папки. На один маршрут допускается
1–32 ожидающих задания; выбранный рабочий лимит probe — 4. Переполнение возвращает
IMAP_QUEUE_FULL, без скрытой повторной отправки. Между непустыми очередями действует
round-robin. Одновременно выполняется одна операция. Настраиваемый MinInterval
ограничивает частоту начала операций, а не отдельных IMAP-команд.

В существующем probe/serve все Ensure, APPEND, Page, Delete и Absent проходят
через эти маршруты. Аккаунт остаётся общим для пользователей; распределения
«пять аккаунтов первому, пять второму» нет. Период опроса probe не изменён.
Это локальный диспетчер, **не распределённый ограничитель соединений/команд**
всех клиентов и сервера. В будущем server leases должны дополнять его.

При отмене ещё ожидающее задание удаляется из очереди. Для уже запущенного
задания вызывающая сторона дожидается фактического завершения: потерянный ответ
APPEND не превращается в безопасное «ничего не было отправлено». Close отменяет
текущую работу, завершает очередь и присоединяет worker. Переподключение и retry
на этом уровне отсутствуют. Transport обязан соблюдать context; mailbox.Client
ограничивает каждую операцию 30 секундами. Буферы синхронных вызовов остаются
во владении вызывающей стороны до возврата, изменять их конкурентно нельзя.

## Управляющая почта

Новый пакет `mailcontrol` отправляет один канонический control frame в одном
Noise record. Раскодированное MIME-тело имеет вид `ITC1 || Noise record`.
Максимальный record — 4272 байта, плюс 4 байта маркера. Маркер служит только для
демультиплексирования с DATA/ITQ1 и не является доказательством подлинности.
Open проверяет Noise binding, направление, replay и канонический control codec.

`secure.Epoch.OpenControl` проверяет тип ДО фиксации replay counter. Добавление
поддельного ITC1 к настоящему DATA не может сделать этот DATA «уже полученным».
Тест проверяет, что после такого отказа обычный Open по-прежнему принимает DATA.
Входящий владелец сессии обязан заранее иметь место для возвращаемого frame;
успешную расшифровку нельзя терять из-за заполненной downstream-очереди.

Sender принимает отдельный provisioned control journal, scope, папку, текущую
Noise epoch и пользовательский IMAP Route. До APPEND последовательно выполняются
Issue → Prepare → Start. Размер учитывает фактический MIME. DATA не проходит
control codec и не может расходовать эту квоту. После любой ошибки APPEND attempt
остаётся Unknown. SendResult возвращает его ref даже при ошибке. Закрытие grant
освобождает только неиспользованный резерв, не физический расход attempt.

Отдельный control journal — явный контракт интеграции. NewSender проверяет
совпадение user/session с Noise, а journal проверяет account/folder/лимиты.
NewSender сам не создаёт и не разрешает квоты, не инвентаризирует ящик и не
выдаёт клиенту DATA grants.

## Когда разрешена очистка

Reclaim вызывается владельцем после семантического подтверждения, сделавшего
управляющее сообщение ненужным, либо после fencing его сессии. Успех APPEND
сам по себе не разрешает очистку. Sender не генерирует ACK-of-ACK и не принимает
решений по таймеру. Он сверяет полное тело с durable digest и сохраняет locator,
затем Delete повторно проверяет точное письмо, удаляет его и подтверждает
отсутствие. Только после этого journal.Deleted освобождает квоту.

RecoverDeletion покрывает сбой после EXPUNGE до записи Deleted: нужен ранее
сохранённый UID и тот же UIDVALIDITY. Unknown APPEND без locator нельзя списать
на основании пустой папки. Инвентаризация неизвестных исходов без locator и
непрерывное планирование повторов/очистки остаются задачей session runner.

## Чтение страниц

Page по-прежнему ограничен 16 UID, но использует один UID FETCH диапазона вместо
16 отдельных запросов. UID-дыры после EXPUNGE допустимы. Поля UID/size/body,
повторы, границы UID и размер literal проверяются. Cursor продвигается только
после успешного получения всей страницы; при ошибке возвращается исходный.
Бюджет ответа ограничен числом запрошенных UID × (MaxMIME + 8192), каждый MIME
ограничен 2 MiB. Это верхняя граница памяти, а не типичный размер ITOM-пакета.
Пустая страница не делает FETCH. SELECT остаётся для актуального UIDVALIDITY
и UIDNEXT. Нельзя трактовать эту оптимизацию как измеренный RTT на Rambler.

## Проверенная цепочка и оставшаяся граница

`datapath.TestDATAOverTLSIMAPToRealTCPAndBack` теперь передаёт через настоящие
TLS IMAP соединения activation, coordinator offer/ack, grants, OPEN/OPEN_OK,
usage, receipts, window credit, FIN/ACK, GC и grant retirement. Wallet OpenBound
выполняется после аутентифицированного coordinator offer. Upload 52 KB и download
70 KB доходят до настоящего локального TCP-сервера с half-close. Все управляющие
записи остаются в control journal до fencing тестовых владельцев и затем
подтверждённо удаляются. Noise handshake fixture создаёт эпохи в памяти; отдельный
probe-тест проверяет Noise handshake через IMAP. Тест использует явный driver и
не является автономным многопоточным session runner.

**serve всё ещё qualification service.** Нет подключённого живого SOCKS→IMAP
runner, распределённого account governor, автоматического рабочего demux/read
pump, полной DATA reconciliation и Android VPN backend. Новый исходник даёт
реальные почтовые компоненты, но не заявляет готовый VPN или измеренную скорость.
Следующий шаг — один owner loop с bounded событиями и worker jobs, затем CLI
SOCKS endpoint поверх него; Android подключается к тому же работающему ядру.
