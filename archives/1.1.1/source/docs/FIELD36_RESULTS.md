# ITOM FIELD36: разбор отказа подключения и диагностическая сборка

Ревизия: `transport-s1-perf5-field15`. Основа: FIELD35, SHA-256 `0a023e7f9778baf0df11af4b7a87a413683e23f689da811083776ca05eb8be2e`.

## Что установлено по реальным логам

Клиент и сервер действительно используют FIELD14. В двух длительных новых серверных запусках зарегистрировано **302 ошибки IMAP_CONNECT_FAILED** (202 и 100). В последнем запуске все 20 комбинаций аккаунт/пользователь получают первый отказ через **15,000–15,001 секунды**. В логах этих запусков нет успешного подключения транспортной линии, перехода к TLS/LOGIN или транспортному handshake. Сам отказ этих линий возникает до TLS. Состояние отдельных фоновых сокетов без записей об их подключении из этих архивов установить нельзя.

В трёх новых клиентских запусках все 10 аккаунтов устанавливают IMAP-соединение и переходят в handshake_wait, ни один не достигает ready. Повторно читаемые старые пакеты из почты не подтверждают доступность нового сервера. Итоговый diagnostics.json снят после выключения VPN; состояние OFF не использовалось как доказательство первоначального отказа.

Код IMAP_CONNECT_FAILED в FIELD14 выдаётся исключительно при отказе net.Dialer.DialContext, **до TLS**. Однако исходный net.OpError / net.DNSError заменялся одной строкой. Поэтому архивы подтверждают стадию DNS/TCP, но не доказывают конкретный сбой DNS, маршрута, порта, фильтрацию или лимит провайдера. Прежний долг grants и балансировщик нагрузки на этой стадии ещё не выполняются.

## Изменения FIELD36

- Подключение сохраняет безопасные стадии dns / tcp / tls / greeting / login и категории timeout / not_found / refused / unreachable / permission / certificate_authority / certificate_name / certificate_invalid / rejected / closed / protocol / other.
- В трассировку добавлено imap_connect_failed с длительностью; в снимок линии — LastConnectStage и LastConnectReason. Успешная новая попытка очищает эти дополнительные поля.
- Исходные коды ошибок, их сравнение в retry/fallback, тайм-ауты, системный DNS, пользовательский Android dialer, TLS-проверка и сетевые политики сохранены. Сырые ошибки провайдера не сохраняются и не выводятся.
- Winsock-коды отдельно сопоставлены с категориями, поскольку POSIX-константы syscall на Windows отличаются от реальных кодов сокетов.
- Команда imap-check проверяет ровно один существующий аккаунт через штатный Dial, выполняет LOGIN и NOOP, закрывает соединение. Она не создаёт папки и не выполняет SELECT/APPEND, не запускает туннель, не изменяет grants, журналы или квоты.
- Формат и возможности протокола не менялись. Для диагностики можно обновить только VPS; текущий Android FIELD14 совместим с FIELD15.

Новые компактные тесты проверяют реальные локальные DNS NXDOMAIN / DNS timeout, TCP refusal, срок подключения, проверку TLS-сертификата, отказ LOGIN, сохранение безопасной стадии в логах и read-only проверку одного TLS/IMAP-сокета. ## Ограничения и следующий шаг

**Это диагностическая сборка. Восстановление реального соединения пока не подтверждено.** Нагрузочный транспорт в этом изменении не перерабатывался; новые измерения скорости и RTT не выполнялись. Исторические model PASS FIELD35 не отменяют текущий реальный отказ подключения. Android/APK, Windows execution и настоящий VPS здесь не проверялись.

Собрать server, передать подходящий бинарник в /tmp, выполнить установку и imap-check. Пришлите строку account / stage / reason / elapsed_ms; она определит следующий шаг. Если отдельная проверка успешна, нужны свежие серверные логи после её выполнения — тогда следует искать отличие одиночного подключения от штатного запуска.

Windows PowerShell:

```powershell
python .\ITOM_TRANSPORT_FIELD36_SOURCE.zip server --expect-revision transport-s1-perf5-field15
```

VPS amd64, бинарник уже в /tmp:

```bash
chmod 755 /tmp/itom-linux-amd64 && sudo /tmp/itom-linux-amd64 install && sudo /tmp/itom-linux-amd64 imap-check --account a01
```

При ошибке последняя команда намеренно возвращает ненулевой exit code; диагностическая строка перед ним — нужный результат. Если a01 удалён, используйте ID существующего аккаунта. Для arm64 нужен itom-linux-arm64.
