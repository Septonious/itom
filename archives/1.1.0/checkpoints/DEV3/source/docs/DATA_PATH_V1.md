# DATA path v1 — data-1

Обновления startup, SOCKS и повторяемого final grant retirement в session-1
описаны в SESSION_STAGE_V1.md; они заменяют соответствующие пункты «следующего блока» ниже.

## Что реализовано

`core/datapath` соединяет ранее отдельные `flow`, `recovery`, `session`, `secure`,
`wallet`, `journal` с заданиями физической записи и настоящими TCP-сокетами.
Это компонент транспорта. Production session runner, интеграция в `serve` и
Android не реализованы; сквозной driver находится в integration_test.go.

### Engine: один владелец состояния

Владелец последовательно вызывает Engine; дисковые операции, DNS, IMAP и
сокеты выполняются снаружи. Engine не делает I/O. Активировать поток можно лишь
после аутентифицированного OPEN_OK либо принятого результата серверного dial.
Все события содержат generation; Stop отменяет контекст заданий и запрещает
применять поздние результаты к закрытой сессии.

Queue принимает байты лишь в рамках stream/session credit, RAM и metadata
лимитов. Приём поддерживает перестановку и дубликаты DATA. RECEIPT освобождает
логические байты, а не физические письма; удаление требует отдельного
подтверждения GC. Delivered продвигает окно только на фактическое число байт,
записанных в TCP, в том числе при частичном Write с n>0 и ошибкой.

STATUS периодически публикуется для всех активных потоков. Так восстанавливается
и потерянный первоначальный WINDOW, когда ещё нет DATA. Missing ranges приводят
к аутентифицированным NACK; только NACK разрешает repair. На один item доступны
не более двух repairs; повторный NACK не создаёт дополнительную запись.
Таймер не запускает слепой APPEND. После deadline вызывающий код обязан завершить
сессию: распределённый RESET с окончательным учётом пока не соединён с Engine.

FIN допускается до DATA. TCP CloseWrite разрешён лишь когда всё до final offset
получено и доставлено сокету. FIN_ACK подтверждает наблюдение final offset,
а не доставку в конечное приложение. Поток удаляется после двух FIN, FIN_ACK,
доставки RX и RECEIPT всего TX. Компактная запись final отвечает на повторный
FIN; ID не используется повторно в этой сессии.

Default bounds: 12 MiB logical TX, 12 MiB RX, stream window 256 KiB,
128 active streams, 4096 items, 8192 attempts, 4096 metadata entries,
2 MiB физического in-flight бюджета на аккаунт, deadline 120 s, STATUS 2 s.
Это начальные ограничения компонента, не измеренные оптимальные настройки.
Физические durable grants — независимое обязательное ограничение.

### Writer: физическая запись только после durable charge

Begin создаёт Job, но сам по себе не разрешает APPEND. Копии Job делят один
атомарный claim; задание можно выполнить один раз. Size предсказывает точный
размер single-frame Noise/MIME, worker сверяет размер до расходования квоты.

- WriteRemote проверяет пользователя/сессию/аккаунт, шифрует и вызывает
  wallet.Spend до APPEND. Возвращённый UsageReport требуется повторно передавать
  через аутентифицированный control lane до подтверждения. Отмена после Spend
  не отменяет durable расход. Ни timeout, ни отсутствие письма не освобождают его.
- WriteLocal делает journal.Prepare и durable Start до APPEND. Отмена до Start
  отменяет только Prepared. Неизвестный результат APPEND остаётся Unknown.
- Ошибка APPEND консервативно считается CommitUnknown. Автоматического повторного
  APPEND внутри writer нет. Потерянный ответ не освобождает физическую квоту.
- OpenRemote сверяет session/user, точный MIME size, decoded size, digest,
  descriptor ordinal/batch и Noise binding/direction/replay. Внешний ITQ1 marker
  не доказывает принадлежность письма. Report должен быть аутентифицирован заранее,
  принят журналом и относиться к аккаунту/папке, которую сканирует вызывающий код.

Объекты wallet/journal/Epoch синхронизируют собственное состояние. Engine требует
одного владельца. Один mailbox.Client сериализует свои команды. Для задания
записи сокета нужен единственный владелец данного направления.

### TCP exit

OpenBook и одноразовый token не позволяют повторному OPEN или Dial создать
второе соединение. Только один Complete принимает сокет; результаты остановленной
или устаревшей сессии закрывают непринятые сокеты. Повторный Complete не закрывает
уже принятый сокет. Отдельный mutex защищает book и map, сеть выполняется вне него.

DNS разрешается один раз в IPv4, далее подключение идёт к проверенному числовому
адресу. До 16 результатов; default policy отклоняет private/loopback/link-local,
multicast и перечисленные специальные IPv4 диапазоны. AllowPrivate — явный
параметр для теста/операторской политики, не автоматический fallback. IPv6 exit
пока отсутствует. До 128 sockets; MaxDials <= MaxSockets; общий dial deadline 15 s
включает ожидание слота. Stop отменяет dial и закрывает принятые сокеты.

WriteSocket передаёт не более wire.MaxData (32 KiB), сохраняет n вместе с err,
ограничивает Write 30 секундами и закрывает сокет по отмене контекста. Полный
read pump и очереди worker-result в production runner ещё предстоит подключить.

## Проверка

Сквозной тест использует локальный TLS IMAP server, проверенный TLS certificate,
два IMAP-соединения, реальное Noise-рукопожатие, durable ledger/wallet, настоящий
TCP listener/socket. Upload около 52 KiB, download 70 KiB проходят APPEND/FETCH,
декодирование и проверку целостности; обе стороны выполняют half-close.
Проверяются RECEIPT раньше completion, exact-body GC и нулевой остаток буферов
и физических attempts после подтверждённой очистки.

Control frames здесь шифруются/расшифровываются в памяти. Их доставка через
почтовый control lane не реализована этим тестом. Grant/store identity задаётся
явно при подготовке теста, не согласуется сетевым startup-протоколом.

Отдельные fault tests покрывают lost DATA/window, перестановку, дубликаты,
ограничение repairs, частичный Write, отмену, поздние/повторные Dial/Complete,
запрет APPEND без квоты/при чужой session, Unknown APPEND с сохранением долга.
Полный Go gate включает race detector и vet. Длительный soak, реальные потери
связи и DATA через Рамблер не проверены.

## Следующий блок интеграции

1. Authenticated coordinator store identity и startup capability negotiation.
2. Повторяемое подтверждение окончательного закрытия grant, включая потерю
   последнего GC status; сейчас закрытая полностью очищенная запись может
   исчезнуть до получения этого ответа wallet. Не выдавать текущий путь за
   надёжный reconnect/retirement-протокол.
3. Account-wide connection/rate governor для общего пула двух пользователей.
4. Mailbox control lane, ограниченные очереди и session runner; подключение
   Engine/writer/TCPExit к serve и клиентскому TCP входу.
5. RESET/rekey/reconnect lifecycle, затем Android VPN и реальные испытания.

## Сопутствующие изменения

В менеджере нет typed DELETE/PURGE подтверждений. Выбор операции + ID запускает
её; проверки остановки службы, неизменности аккаунта и отчёт о частичном результате
сохранены. Журналы не сбрасываются при очистке папок.

В probe устранена обязательная секундная пауза после отправки PING. Активный
опрос — 100 мс до 5 секунд, затем 1 секунда; сервер ускоряется только на короткий
период после аутентифицированного handshake для ещё не отвеченной сессии. IDLE,
provider governor и непрерывная высокочастотная нагрузка сюда не добавлены.
Исходные пользовательские RTT 2.359/1.291 s отсчитывались после handshake и
включали polling и IMAP I/O. Новый RTT пока не измерен; цель WSIT 0.4–0.6 s
остаётся пользовательским ориентиром, не обещанием этой ревизии.
