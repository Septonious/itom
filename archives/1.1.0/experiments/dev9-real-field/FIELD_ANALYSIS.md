## Rework under evaluation

* Protect one real split DATA receiver when at least five carriers are usable; retain legacy mixed/small-pool service. Both endpoints initially select the same account order. Existing in-progress work finishes normally.
* Use the protected DATA mailbox for short DATA and wake that receive service on demand. Its socket can lend a free command turn to APPEND when control is busy. Only admission is raced; cancel and join the losing waiter before invoking APPEND exactly once. IDLE exits through DONE, while partial BODY reads remain uninterrupted. Unknown outcomes are returned without a transparent resend.
* Keep APPENDUID hints from borrowed sockets bounded and available to cleanup. They remain discovery hints; exact BODY/incarnation/deletion proofs govern refunds.
* Derive smaller bulk publication units from genuinely free duplex capacity below the maximum-BODY floor. Keep a complete160KiB FAST collector cushion, at least128KiB bulk BODY capacity in each direction, every historical charge, and all original physical ceilings. Authenticated accepted grants advise sender batch sizing; they never authorize spending beyond the wallet.

The original100Mbps full/tail,750ms light/loaded,1500ms OPEN, zero half-second useful-byte stall checks and all accounting/recovery assertions remain. An old unit assumption that a maximum512KiB BODY was also the minimum permissible transfer size is replaced with a minimum-complete-duplex fail-closed boundary; no performance threshold changes. The new exact debt readiness case must fail on unchanged DEV8 and RC2 rather than silently omitting a08.

Initial local deterministic borrow/IDLE/one-APPEND/cancellation/debt tests pass, including race instrumentation. The first local application run still fails two TLS response-header deadlines despite completing48 light probes; it is not a qualified result. Matched CI and further experiments decide selection. No100Mbps restoration, universal sub200ms RTT, or field fix is claimed by this document.

## Follow-up selection errors found before packaging

The first prototype restores readiness but regresses fixed MULTI rates/tails and is rejected (raw V1 results preserved). Dynamic lending then raises matched capped upload from about78 to100Mbps SINGLE and61 to85Mbps MULTI without a material download loss. Explicit-request DATA search improves fixed idle means to187–206ms in a subsequent paired comparison, but mobile/light and the1100ms loaded-chat checks still fail. The grace-only5–50ms trial has mixed fixed stalls/tails and is not selected.

A deterministic new red/green regression exposes a prototype routing defect: the old mixed-layout hysteresis retained different first-ready quiet accounts at the two endpoints, even after their healthy account sets became identical. Old startup affinity could also displace the newly protected path. The revised split selector depends only on the current eligible account set; mixed-layout hysteresis remains unchanged. When eligibility changes, previously admitted BODYs finish normally. The affected tests cover both idle and existing bulk flight and different startup orders. This is a correction to the unpublished prototypes, not a retroactive claim that DEV8 had a split reserve.
