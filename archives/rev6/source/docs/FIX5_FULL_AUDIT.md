# ITOM 0.4.0-dev1: анализ исходников и build-fix-5

Дата: 2026-09-24. Основа анализа — точный архив fix4 с SHA-256 `b0edc393f69752c511681391f53dc4b90699d5419b40bfff7c899b5b3baa0495` и новый журнал Windows PowerShell пользователя. Изменения подготовлены в отдельной рабочей папке от этих исходников; устаревшие рабочие копии не использованы.

## Почему предыдущая команда завершилась ошибкой

В последнем журнале `:domain:test`, `:app:compileDebugKotlin`, `:app:compileReleaseKotlin` и `:app:assembleDebug` прошли. Неуспешна только `:app:lintDebug`: одна ошибка `QueryAllPackagesPermission` и 11 предупреждений. Полный вывод фикса 4 подтвердил причину; прежняя гипотеза о втором diagnostic в LocalContext не подтверждается.

Это проверка обоснованности широкого доступа к каталогу пакетов. Простое удаление QUERY_ALL_PACKAGES или замена на launcher queries нарушило бы согласованную возможность выбирать системные приложения и пакеты без запускаемого экрана. В fix5 разрешение сохранено; только на его объявлении добавлено документированное исключение Lint. Подробности и первичные источники — `PACKAGE_VISIBILITY.md`. Остальной Lint остаётся обязательным.

Предупреждение Gradle о `kotlinOptions.jvmTarget` исправлено переходом на типизированный `kotlin.compilerOptions` и `JvmTarget.JVM_17`. Версии AGP/Gradle/Kotlin/Compose не менялись. Сообщения SDK XML v3/v4 и strip libandroidx.graphics.path.so не были причиной отказа: после них в журнале успешно прошли компиляция и упаковка. Их исчезновение этим патчем не заявлено. Содержимое всех 11 предупреждений Lint в присланном журнале отсутствует; теперь launcher выводит каждое Warning вместе с Error/Fatal.

## Объём анализа

Просмотрены все 18 Kotlin-файлов, четыре Gradle Kotlin-скрипта, gradle.properties и ProGuard, четыре XML-файла и четыре Python-скрипта. Проверены связи между domain, main/debug/release, манифестами, зависимостями, тестами и командой выдачи артефакта. Это статический анализ всего текущего комплекта, а не заявление о выполненной Android-сборке или проверке на устройстве.

## Исправленные дефекты помимо Lint

| Проблема | Исправление | Проверка |
|---|---|---|
| Stop из уведомления не имел generation и мог остановить новую сессию | Immutable PendingIntent имеет уникальный URI с generation; extra проходит атомарную проверку SessionMachine перед Stop | Два новых Kotlin-теста для устаревшей и текущей команды; выполнятся локально |
| Между проверкой POST_NOTIFICATIONS и notify разрешение могло быть отозвано | Обрабатывается SecurityException от notify; обычный предварительный permission check сохранён | Анализ ветвей; проверка на устройстве остаётся |
| Start во время записи удаления мог возобновить сессию удаляемого профиля | После завершения удаления повторно проверяется profileId активной сессии | Анализ порядка async-операций; сценарий включён в device checklist |
| Pending export хранился в remember и исчезал при rotation | Для профиля сохраняется только публичный profileId, для диагностики — отчёт без секретов | Анализ saveable-state и обработчика результата; устройство остаётся |
| После возврата из Android Settings статус уведомлений мог остаться прежним | Lifecycle observer перечитывает разрешение на ON_RESUME и удаляется при disposal | Анализ регистрации/удаления observer; устройство остаётся |
| Повторная проверка приглашения могла оставить старое подтверждение доверия | parsed/trusted сбрасываются до начала проверки | Анализ успешной/ошибочной ветвей |
| Чтение импорта и vault могли некорректно трактовать отмену coroutine | Проверка отмены при чтении; CancellationException не преобразуется в ошибку QR/vault | Анализ catch/finally; лимиты и очистка буферов сохранены |
| Ошибка создания dist или записи build-report.json могла оставить build.lock | dist создаётся до lock; unlock выполняется во вложенном finally, исходная ошибка сохраняется | Два offline-теста для ошибок файловой системы |
| Нулевой exit code Gradle был единственным условием выдачи APK | Дополнительно проверяются читаемые JUnit/Lint-отчёты, отсутствие ошибок/пропусков, ненулевое число тестов | Offline-сценарии missing/failed/skipped/malformed reports; файл не выдаётся |
| При раннем сбое отдельные независимые задачи и предупреждения скрывались | Gradle --continue сохраняет неуспешный итог, но собирает независимые diagnostics; Warning печатаются тоже | Offline-тест полного сценария сборщика с несколькими ошибками |

`--continue` не превращает ошибку в успех. Baseline, глобальные lint disable и ignoreFailures не добавлены. Единственное точечное исключение для QUERY_ALL_PACKAGES проверяется перед Gradle; проверка отвергает отсутствие разрешения, дубликат и широкое tools:ignore.

## Что реально проверено

- Прошли **30 Python/offline-тестов** с `PYTHONUTF8=0`, `PYTHONWARNDEFAULTENCODING=1`, `EncodingWarning` как ошибкой. Это включает прежние 22 и восемь новых тестов; некоторые содержат несколько отрицательных сценариев.
- Проверены Python AST, четыре XML, границы source sets, корректная заготовка pair ID, manifest exception и включённые build gates.
- Для проверки launcher выполнены положительный и отрицательные сценарии с подставным процессом Gradle и XML-отчётами. Это тесты Python-оркестрации: Java/Gradle/SDK не запускались, тестовый файл-артефакт не является APK.
- Подготовлены **32 Kotlin/JUnit-теста**: прежние 30 и два новых на notification Stop. В чате они не запускались. Присланный журнал подтверждает успешный domain:test только для предыдущей ревизии fix4.
- Финальный source ZIP проверяется через собственную распаковку и target check. Команда android у пользователя повторит JUnit, Lint, release Kotlin и debug APK.

## Границы результата и следующий шаг

Устранена единственная известная блокирующая ошибка из полного последнего вывода Lint. Это не заменяет запуск Android-инструментов на новой ревизии. APK/серверные бинарники и toolchain в чате не собирались/не устанавливались по договорённости пользователя. Для подтверждения fix5 нужны локальная команда из README и проверка на телефоне.

В текущем проекте остаются демонстрационный backend и release без подключённого ядра. TUN/VpnService, IMAP datapath, DNS/protect/bind, серверная регистрация и производительность относятся к следующим инкрементам. G1/G2 этим исправлением не закрываются.

Источники для изменённых платформенных решений: [Kotlin compilerOptions](https://kotlinlang.org/docs/gradle-compiler-options.html), [package visibility](https://developer.android.com/training/package-visibility/declaring), [tools:ignore](https://developer.android.com/studio/write/tool-attributes#toolsignore). Существующие API TileServiceCompat/LocalActivity проверены в предыдущем фиксе и сохранены.
