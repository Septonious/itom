# Native UI 2 · редактор профилей и контраст

Версия 0.4.0-dev3, versionCode 4004, ревизия `native-ui-2`, 24 сентября 2026.

Пользователь считает UI в целом готовым и просит завершить два изменения: полноценное редактирование профилей и устранение чёрного текста на синем фоне. После этой поставки визуальная переработка приостанавливается; следующий этап — функциональная разработка транспорта. Новый HTML не создавался.

## Редактор

В карточке каждого профиля есть явная кнопка «Изменить». Она открывает полный экран с собственными заголовком, Back и закреплёнными Save/Cancel. Редактируются:

- название, восьмизначный User ID, Server ID, общий почтовый provider ID;
- namespace почтовых папок, Pair ID и 32-байтный ключ в Base64;
- набор IMAP-аккаунтов: добавление, удаление, включение/выключение;
- ID и название каждого аккаунта, hostname, порт, логин, пароль.

Аккаунты раскрываются по одному, поэтому длинный список остаётся удобным. Новый аккаунт наследует endpoint первого, но не его пароль или логин. Провайдер общий для всего профиля. IMAPS и проверка сертификата обязательны; внутренние ссылки секретов и локальный profile ID управляются приложением. Поддерживаемый транспортный preset пока один и не превращён в произвольное текстовое поле.

Ранее User ID в UI был недоступен для правки. Новое прямое требование пользователя имеет приоритет: ручное изменение разрешено. Клиент при этом не создаёт пользователя на сервере и не выполняет автоматическую смену серверного ключа. Введённые параметры должны соответствовать серверу.

Черновик хранится в памяти ViewModel и сохраняется при rotation. После process death восстанавливаются только уже записанные данные; секреты в Android saved state не помещаются. Пароли/PSK замаскированы, есть «Показать/Скрыть», экран защищён FLAG_SECURE. Back/Cancel с изменениями предлагает продолжить редактирование или отбросить черновик. Во время commit повторные Save/Back заблокированы.

`ProfileEditing.apply` формирует полный новый документ, а VaultStore проверяет revision, валидирует, шифрует и записывает его под Mutex через AtomicFile. Ошибка в UID, PSK, аккаунтах или конфликт revision оставляет предыдущий документ. Удалённые аккаунты очищают свои credentials, остальные профили изолированы. Старая схема vault читается; демо по-прежнему может не иметь секретов, но позволяет сохранять их при редактировании и не превращается в реальный профиль самопроизвольно.

Активная сессия изменённого профиля перезапускается после успешного commit. Остановленная во время записи сессия остаётся остановленной; неактивный профиль не перезапускает другой. В демо отключённые аккаунты больше не увеличивают счётчик активных линий.

## Контраст

Найдены два источника тёмных надписей: `onPrimary = Background` и наследование стандартного LocalContentColor градиентными контейнерами, которые не являются Material Surface. Теперь тема явно задаёт Ink для наследуемого текста, Scaffold имеет `contentColor = Ink`; primary/secondary containers и выбранные chips также используют светлые надписи.

Градиентные кнопки используют #1266B5 → #145A9C с текстом #ECF4FC. Расчёт контраста на концах градиента: 5.26:1 и 6.36:1. Для primary container — 10.16:1, выбранных chips — 8.65:1. Это числовая проверка палитры, не скриншоты Android. Светло-голубые иконки/ссылки на тёмном фоне сохранены.

## Фактические проверки

- 30 Python/offline-тестов прошли с отключённым Python UTF-8 mode и EncodingWarning как ошибкой; 4 Python/13 XML, source-set boundaries.
- Проведён статический обзор UI callbacks, полного пути draft → validation → encrypted commit → session update, секретов и отмены. Проверены длины положительных hex-ID fixtures и баланс Kotlin delimiters. Это не Kotlin compilation.
- Подготовлены 10 новых Kotlin/JUnit-тестов (всего 42): round trip всех параметров/секретов, удаление credentials, чужие refs и server ID, stale/deleted draft, invalid edits, обязательные real secrets, legacy/edited demo, независимость новых логинов/паролей, redacted diagnostics.
- Android compilation, 42 Kotlin-теста, Lint, APK, Compose Preview и device tests здесь не выполнялись. Они остаются локальным этапом пользователя. Локальные build gates не ослаблялись.
