# ITOM FIELD39 — устойчивость TCP-потоков под нагрузкой

Ревизия `transport-s1-perf5-field18`; архив `ITOM_TRANSPORT_FIELD39_SOURCE.zip`.

Исправлены причины, по которым перегрузка control-очереди, таймаут одного DATA/FIN-потока и потерянный RESET_ACK могли завершить логический owner. Несколько непереданных накопительных управляющих сообщений одного потока объединяются в последнее состояние; подтверждения квот сохраняют отдельный приоритет. Сокет закрывается сразу, а маршрут для RESET_ACK остаётся до аутентифицированного завершения. Отдельный истёкший поток изолируется без списания неподтверждённого физического долга. Локальное переполнение при OPEN_OK отклоняет только новый TCP-сокет. Исправлен ложный reattach по запоздавшему probe или challenge другого клиента.

Импорт в Android показывает полный многострочный JSON без маскирования и галочки подтверждения. Добавлены подсветка без изменения символов/переносов, проверка синтаксиса и схемы, позиция ошибки, форматирование и приём ссылки `itom://import#...`. При ошибке исходный текст сохраняется.

Менеджер сервера использует email при выборе/удалении/проверке аккаунтов, принимает видимый пароль с сохранением пробелов, экспортирует трассировку прямо в `/tmp` и выводит приглашение одной строкой-ссылкой. Стабильные внутренние ID сохранены для совместимости журналов, квот и существующих профилей. Rambler не исключён из конфигурации и доступен вместе с Mail.ru.

Сборка (PowerShell):

```powershell
python .\ITOM_TRANSPORT_FIELD39_SOURCE.zip all --expect-revision transport-s1-perf5-field18 --accept-android-licenses
```

Установка/обновление VPS amd64 после загрузки бинарника в `/tmp`:

```bash
chmod 755 /tmp/itom-linux-amd64 && sudo /tmp/itom-linux-amd64 install
```

Обновить нужно обе стороны, включая новый APK. Экспортированную серверную ссылку вставить в окно импорта; «Проверить и форматировать» раскрывает её как JSON.

Полный Go gate, race, vet и Linux-сборки проверены; подробные результаты и ограничения находятся в `docs/FIELD39_RESULTS.md`. Android compilation/lint/Kotlin/device tests в этой среде не выполнялись. Локальная HTTPS-модель не подтверждает реальную скорость/стабильность Mail.ru или Rambler.

Совместный анализ клиентской и серверной трассировки обнаружил одновременное закрытие физических клиентских IMAP-сокетов в 17:52:17 UTC. Первопричина этого закрытия в имеющихся логах не раскрыта; восстановление реального speedtest необходимо проверить на устройстве. Второй серверный таймаут следует за остановкой клиента (`OFF`, `trace_stop`), поэтому он не используется как самостоятельное доказательство аварии транспорта. Не считаем FIELD39 полевой квалификацией >=75 Мбит/с.
